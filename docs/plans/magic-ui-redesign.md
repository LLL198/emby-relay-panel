# Magic UI 风格界面重构计划

## 目标

在不改变节点、线路、用户、邀请码、登录权限和部署逻辑的前提下，将登录/注册页、用户线路页和管理后台统一重构为 Magic UI 风格，提升层次、动效、可读性和移动端体验。

## 范围

- `panel.py`
  - 重写 `AUTH_UI_CSS`，覆盖登录、注册和账号安全页。
  - 重写 `ADMIN_UI_CSS`，覆盖运行概览、节点、线路、用户和邀请码模块。
  - 仅在必要处调整纯展示性 HTML，例如品牌标识和装饰容器；保留表单 action、字段名、CSRF、ID、data 属性和现有脚本行为。
- `uniproxy.py`
  - 重写 `DASHBOARD_UI_CSS`，覆盖登录后的用户主界面、节点选择、线路创建和线路列表。
  - 保留节点测速、复制、备注编辑、删除和线路创建脚本与接口。
- 不引入 React、Tailwind、Motion、CDN、外部字体、图片或新的构建步骤。
- 不修改数据库结构、后端接口、Nginx、节点部署或权限判断。

## 关键决策

1. 使用纯 CSS 和现有 nonce 脚本实现 Magic UI 的视觉语言：暗色画布、动态网格、径向光晕、玻璃卡片、Bento 数据块、渐变边框、状态脉冲和 Shimmer 主按钮。
2. 认证页保持用户要求的极简内容，只显示品牌、表单、错误/成功消息和必要跳转，不恢复已删除的介绍文案。
3. 后台默认使用暗色主题，同时保留现有主题切换；亮色主题也提供完整配色，避免原有本地偏好失效。
4. 动效只用于背景、边框和按钮高光，不使用高频 JavaScript 动画；通过 `prefers-reduced-motion` 关闭非必要动画。
5. 响应式布局继续以现有断点为基础，移动端保证 44px 以上主要触控高度、横向表格可滚动、导航可横向访问。

## 验证标准

- `python -m py_compile panel.py uniproxy.py` 通过。
- 认证页、用户页和后台五个模块均能在测试请求中渲染，HTML 中不存在未替换占位符。
- CSP nonce、CSRF 隐藏字段、所有表单 action、关键 ID/data 属性保持存在。
- 节点选择/测速、复制、备注编辑/取消、后台搜索/主题/编辑/确认删除脚本仍存在且选择器可命中。
- 320px、移动端和平板断点样式存在，且 `prefers-reduced-motion` 有降级规则。
- `git diff --check` 和仓库现有测试（如有）通过。
- 线上更新前创建仅 root 可读备份；更新后 `uniproxy` 为 active、健康检查返回成功、`nginx -t` 通过且服务错误日志无新增错误。

## 风险

- 三套页面分别内嵌 CSS，容易出现旧规则叠加；本次直接替换对应 CSS 常量，避免继续追加覆盖层。
- 后台表格字段较多，窄屏必须保留横向滚动，不能强制压缩列宽。
- 认证页 CSP 不允许脚本，因此其动效必须完全使用 CSS。
- 线上数据和远端节点操作不属于本次验证范围；部署后只验证控制面健康与页面渲染，不触发新增、删除或下发操作。
