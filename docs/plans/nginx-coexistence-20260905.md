# 已有 Nginx 平滑共存与随机内部端口

## 目标

- 自动部署不停止、禁用或强制接管已有业务 Nginx。
- 已有 Nginx 节点采用“公网前置 Nginx + 本项目本机 sidecar Nginx”模式，通过平滑 reload 接入。
- 空节点继续使用本项目独立 Nginx；线路和证书续期在两种模式下都能正确更新。
- 新增节点时内部 HTTPS 端口默认选择未占用的高位端口，同时保留输入框允许自定义。

## 范围

- 节点自动部署、已有 Nginx 监听端口探测、节点健康检查。
- 线路下发/删除、证书续期、节点删除时的远端配置清理。
- 节点表结构和前端端口提示；尽量复用现有字段，避免不必要迁移。

## 关键决策

- 不再执行 `systemctl disable --now nginx`、服务级 stop 或结束未知 `/run/nginx.pid`。
- sidecar 使用独立的项目目录、PID、配置和本机回环地址端口；前置 Nginx 只增加带项目标记的域名代理配置。
- 每次远端配置变更都先 `nginx -t`，失败时恢复项目文件；通过后使用 `systemctl reload nginx`，不重启前置服务。
- 检测到域名/监听冲突、无法识别 include 入口或无法安全回滚时，部署失败且不修改原 Nginx。
- 随机端口仅作为默认值；自定义端口必须校验范围并在部署前检查可用性。已有 Nginx 时公网端口沿用其 HTTPS 监听，项目内部端口仍使用随机/自定义高位端口。

## 验证标准

- 已有 Nginx 的部署脚本不含停止/禁用原服务动作，能生成前置代理和 sidecar 配置。
- `nginx -t` 失败时原配置与项目临时文件均可恢复。
- 线路新增、删除、证书续期和节点删除只 reload 对应服务，不停止原 Nginx。
- 空用户名默认 root；默认内部端口在高位范围且可被自定义覆盖。
- Python、Shell 语法检查和 VPS/NAT/已有 Nginx 分支回归通过。

## 风险

- 不同发行版的 Nginx include 布局和 systemd 服务名可能不同，需要探测后再写入。
- 既有 Nginx 若存在相同域名、通配 server 或非标准 stream 配置，必须拒绝自动接入，避免改变原业务路由。
- sidecar 与前置 Nginx 之间的 TLS/HTTP 转发、WebSocket 和真实端口展示需要单独回归。
